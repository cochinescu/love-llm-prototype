# PROTOCOL.md — versioned analysis record for the Love paper

This file records the criteria, mechanism revisions, and evaluation stages used
in the repository. Protocol amendments and their corresponding outputs were
committed together, so Git history does not independently establish temporal
precedence. This is therefore not a preregistration record. **FROZEN** means a
value is enforced by a runner, hash, or test; **PROVISIONAL** identifies a value
used during development; **RECORDED** describes an observed workflow step.

The plan (`../planning-docs/2026-07-11-love-paper4-plan.md`) defines what each
item is for. Integrity rule (FROZEN): `results/model_predictions.csv` and
`results/predicted_shape.json` are generated by the LLM-free formal model
(`lovellm/curve.py`) and checked against `FROZEN_model_predictions.sha256`;
`scripts/reproduce.py` errors if the file no longer matches its hash. The
predicted curve is generated from the stated model constants rather than fitted
to measured runs. The hash establishes integrity, not an external timestamp.

| item | status | value |

| pref-estimate EWMA | PROVISIONAL | 0.20 |

## W2 revision R1 — "probe-guarded partiality"

**Recorded trigger:** the v1 real grid failed the capability-equivalence
TOST (mean quality diff −0.084, 90% CI [−0.109, −0.060] vs ±0.05): the full
arm's probe responses spend part of their budget on relationship content
(preference/need topics, markers), which the probe-relevance quality score
correctly counts against them. Per the paper's §10 forward path 1, the
mechanism is revised so relationship content cannot displace probe-relevant
content; the instrument (quality score, TOST rule, margins) is UNCHANGED.

| item | status | value |
|---|---|---|
| guarded conditioning mix | FROZEN (R1); effective values recorded 2026-10-06 (Amendment A2) | NOMINAL probe 0.75 / pref 0.15 / need 0.10 on probe responses (was 0.5/0.3/0.2). `pipeline._conditioning` renormalizes the mixture to unit sum, and `othermodel.need_topics` returns a vector summing to 2 (probe and pref vectors sum to 1), so the EFFECTIVE weights are 0.6818 / 0.1364 / 0.1818 for R1 (relationship share ≈ 32%, not 25%) and 0.4167 / 0.25 / 0.3333 for V1. |
| marker cap | FROZEN (R1) | at most 1 shared-reference marker per probe response (top salience; was uncapped) |
| weight-faithful renderer | FROZEN (R1) | the prompt's word list apportions its 16 words to the top topics IN PROPORTION to conditioning weight (largest remainder) — a fixed per-topic count silently flattens the mix the mechanism set (the v1 renderer's defect, found in calibration) |
| context excerpt cap | FROZEN (R1) | 12 context tokens in the rendered prompt, same cap for every condition; the original renderer's 60-token excerpt was the second contamination source found in calibration. NOTE (A10): with this cap, surplus context slots do not change the rendered excerpt or marker list |
| everything else | UNCHANGED | all other constants, arms, metrics, margins, decoding, grid sizes identical to the W2 freeze |
| revised prediction | FROZEN (rule) | analytical curve re-derived for R1 constants (a_align = 0.25·0.7 = 0.175; p_ref_max = 1·p_emit/REF_CAP ≈ 0.35) and hash-checked in `results/real_v2/`; the original prediction file is retained |
| calibration step | RECORDED | two calibration iterations on the calibration split (2 seeds, full + base arms): guarded mix + marker cap produced −0.077; adding proportional word allocation and the context cap produced −0.009 with final D ≈ 0.23–0.24. Evaluation used different generation seeds but the same personas, probe battery, and base model. Repository history does not independently timestamp this sequence. |
| reporting rule | FROZEN | the paper reports BOTH grids: v1 as the measured cost of unguarded partiality, v2 as the revised mechanism's test; a second TOST failure is reported as such and the hand-off stays undischarged (no further same-session revision) |

## Terminology checklist (the §2 reconciliation, enforced during writing)

FROZEN: the paper's own constructs are never described as "improved theory of
mind" or "empathic access"; "understanding" always means user-particular state
estimation from accumulated relationship data; ToM-benchmark vocabulary appears
only when discussing others' work. The other-model's outputs are estimates in a
data structure. R's `trust` is a stored scalar with a defined update rule.
